# 电商倒卖与代购：市场做法、数据采集和诊断调研

调研日期：2026-09-11。适用场景：2026 年 10 月 2 日—7 日在东京，预算上限 1 万元，国内闲鱼与得物，海外未开通。本文是调研与建议，不是采购单或已批准的开发规格。

## 结论

可验证的工具与卖家案例共同支持这样的流程：**发现候选 → 匹配准确商品 → 验证需求与竞争 → 计算完整成本及最高采购价 → 小量采购 → 跟踪销售和库存 → 用实际回款校准下一批。**

对本项目，建议从国内销路反查日本货源：闲鱼建立可持有商品观察池，得物建立准确货号/尺码的周转观察池；爬虫围绕这两个池持续收集证据。对候选的描述和市场价格，不等于真实买家或已经成交。

依据以平台、工具商官方文档和一个具名卖家案例为主。工具商案例存在营销选择偏差；本次没有访谈中国卖家，也没有登录用户闲鱼/得物卖家端，不能声称这些做法代表行业多数或能保证收益。以下“建议”均为结合资料与用户条件的判断。

## 1. 市面上可以核实的做法

### 1.1 线上/线下零售套利：扫描找线索，二次诊断决定买不买

Tactical Arbitrage 提供从采购网站匹配 Amazon 商品及反向查找货源的能力；它的官方帮助页专门处理数量不匹配、商品未匹配、缺货与重复商品目录等问题。这说明同品识别本身就是选品流程的一部分。[Tactical Arbitrage](https://tacticalarbitrage.com/)、[匹配问题说明](https://tacticalarbitrage.threecolts.support/en/articles/10241082-other-filters-explained)

SellerAmp 将销售资格、费用、利润、最高采购成本、卖家报价和库存估计、历史走势放在同一个商品分析界面；手机支持条码搜索，适合店内判断。销售量/时间等预测指标应按估计理解。[SellerAmp 功能](https://selleramp.com/features/)

具名案例：2025-12-10，SellerAmp 发布 Amazon 卖家 Emily（CrazyFlippinMom）的工作流。她先用 Tactical Arbitrage 找线索，再核查能否出售、主要报价变化、竞争者库存、销售速度、费用和历史价格是否异常。这里借鉴的是检查顺序，不引用其盈利宣传作为收益证明。[案例原文](https://selleramp.com/tips-and-tutorials/turn-tactical-arbitrage-leads-into-profit-sas-case-study/)

**适用到你：**日本网页/门店发现折扣后，系统必须回答“国内是否同一规格、需求如何、所有成本扣完还有多少”。店内输入链接、条码或货号应能得到最高采购价，而非只显示一个 ROI。

### 1.2 二手与收藏品：研究实际卖价，管理长尾库存

eBay Product Research 提供最长三年销售研究、实际成交价（含议价成交）、价格区间、运费和卖家数量等信息，并可筛选品相、商品标识及买卖家位置。页面还明确普通已售搜索与研究工具的覆盖和口径不同。[eBay 官方研究说明](https://www.ebay.com/help/selling/selling-tools/research?id=4853)

Vendoo / List Perfectly 提供多平台刊登、库存记录、成交追踪及其他渠道下架能力；不同功能依赖套餐、平台和连接状态。这些工具主要服务其支持的海外市场，不能推断能直接管理闲鱼/得物。[Vendoo 帮助中心](https://help.vendoo.co/en/)、[List Perfectly FAQ](https://listperfectly.com/faq/)

**适用到你：**闲鱼持有型要关心稳定需求、品相/版本差异、持有天数和退出价格。耐存放不代表有流动性；库存要能定位、复价、降价和复盘。若同一实物跨渠道上架，成交后必须同步减少可售库存。

### 1.3 标准化潮流商品：准确规格、买卖报价、快速周转

StockX 明确区分“Sell Now”和“Ask”：前者接受当前最高买价，后者是卖家挂价等待匹配。即使同款也要对应具体尺码。匹配成功之后再进入查验和后续结算流程。[StockX 买卖报价说明](https://stockx.com/help/en-GB/articles/What-is-the-difference-between-sell-now-and-an-ask)

得物官方协议说明它使用商品竞价模式，并按商家出价页面的标准收取费用。其技术文章显示商品能否出售有审核和状态条件，履约也存在寄平台查验与直接寄买家等不同流程。[得物协议](https://dewu.com/usage)、[商品状态体系](https://tech.dewu.com/article?id=91)、[履约流程](https://tech.dewu.com/article?id=72)

**适用到你：**得物周转型要以货号+尺码+版本为单位，记录可售状态、卖家预计到手金额、竞争价格、真实成交/需求证据和发货期限。不能把 StockX 的即时买盘功能当作得物已验证的能力；得物出现最低卖价不代表你有即时接盘方。

### 1.4 供应商经营：从单次捡漏走向重复补货

Seller Assistant 将供应商报价单、商品匹配、盈利筛选、采购订单、入库及调价串在一起。店小秘采购建议会考虑订单与 SKU 配对、库存和待入库数量，避免把已在途的货重复采购。[Seller Assistant](https://help.sellerassistant.app/en/articles/7050085-what-is-seller-assistant)、[店小秘采购建议](https://help.dianxiaomi.com/article/1483)

**适用到你：**第一趟发现确实能卖的准确商品后，保留供货链接、采购批次和实际成本。后续补货量由自己的成交和在途决定；不要只因又发现相同价差就继续买。

### 1.5 代购与集运：订单和包裹分开管理

Superbuy 的公开流程是提交商品链接、采购、进入仓库，再办理包裹运输；费用包含商品、运输及相关服务。此处只参考流程，不构成推荐其服务或确认本次可用。[服务说明](https://www.superbuy.com/)、[费用构成](https://login.superbuy.com/en/page/guide/feecomposition/)

**适用到你：**商品选择、采购订单、客户订单和运输批次应独立关联。你的一趟飞机相当于一次跨境运输批次，落地快递属于后续包裹；两段不能共用一个“已发货”状态解释所有进度。

## 2. 哪些数据靠什么获得

| 来源 | 已核实的能力/现状 | 当前可采取的方法 | 不能推断的事情 |
|---|---|---|---|
| 日本零售网页 | 商品详情可用于研究采购端；具体商店采集可用性本轮未实测 | 先验证少量目标商店的公开页/许可接口，提取含税价、规格、供货与时间 | 网页有价格不等于东京门店有货；优惠可能有限定条件 |
| Keepa | 官方提供 Amazon 商品与价格历史、报价、跟踪等 API | 有日亚采购需求时，先验证日本站/目标 ASIN 覆盖再考虑付费 | Amazon 数据不能代替闲鱼/得物销售数据，销量排名也不是精确成交量 |
| eBay Product Research | 卖家端可以研究真实成交和历史趋势 | 开通后先用官方界面研究；导出能力及使用方式按账号核实 | 能看界面不代表能通过 API 批量取全部成交数据 |
| eBay 成交 API | 官方将 Marketplace Insights 标为受限发布；文档入口本次转到需登录页面 | 不将获得权限当作十一的前置保证 | 开发者账号或普通商品搜索 API 不等于拥有成交历史权限 |
| 闲鱼 | 查到开放平台入口，但所见公开文档是小程序能力 | 核实卖家端可导出数据；对允许访问的页面取样，必要时用户提供可读数据 | 本次未核实普通个人可用的全市场成交价/买家名单接口 |
| 得物 | 官方协议、商品状态和履约说明可读；开放平台首页未提供足够可解析的接口细节 | 核验账号可见数据、导出、ISV/API 权限；先获取准确 SKU 和预计到手字段样本 | 第三方写着“得物 API”不证明是官方接口、当前可用或含真实成交数据 |
| 自己的订单 | 需要用户账号授权后的真实记录；本次没有读取 | 平台导出/获授权接口/必要的人工录入 | 买家、订单地址不能由公开商品爬虫补造 |

依据：[Keepa API](https://keepa.com/api-docs/)、[eBay API 准入](https://www.developer.ebay.com/develop/get-started/get-started-on-a-buying-application)、[闲鱼开放平台](https://open.goofish.com/doc/)、[得物开放平台](https://open.dewu.com/)。

采集建议：**许可接口或卖家导出 → 允许的公开页面采集 → 授权可见页面/手工补录。**来源按实际成功率、字段覆盖、更新延迟与维护成本选择。验证码/登录失效/空解析应标采集失败，保留待核验状态，不把失败当成零库存或零销量。

关于第三方工具：供应商的能力宣传只能作为候选线索。付费前至少验证同一商品的货号、尺码、价格含义、更新时间、是否能回到原始证据，以及授权/使用范围。个人在平台下的订单数据和整个市场的订单数据不是同一种权限。

## 3. 两套诊断如何不同

### 闲鱼持有型

建议观察：

- 同款同品相在一段时间内的标价变化，以及可信的历史成交记录（若能获取）。
- 不同卖家的供给、重复刊登、可见求购及自己收到的询价。
- 新品补货、再版、季节变化等可能改变稀缺性的官方信息。
- 购入到成交/回款的天数，含仍未卖出的库存，避免只看成功订单。
- 降价出售、回收或自留时的价值依据；自留只代表偏好，不是现金回款。

输出：适合持有/仅试买/不买；最高采购价；普通售价区间；保守退出价及其可信度；最长持有期；退出时可能亏损；缺哪些证据。

未取得可靠成交价时，标价只能支持“市场要价区间”，不能输出已验证的清仓价。某条记录消失可能是删除、隐藏、下架或成交，应标原因未知。公开“已售”也未必披露最后议价金额。

### 得物周转型

建议观察：

- 准确货号、尺码、颜色、版本、包装附件与平台可售状态。
- 卖家预计收入及包含的费用；可见的竞争报价和时间变化。
- 当前成交证据、成交速度/量的统计口径；有无真正可接受的买盘应单独验证。
- 从日本采购到国内可交寄日的交期风险，不能拿今天报价当作回国时锁定价格。
- 查验、退回、售价下跌后的利润与资金占用。

输出：可采购/等待降价/暂缓；最高采购价；当前预计利润；降价情景下利润；最晚采购与发货日期；是否存在实际订单。

建议将售价下跌 10%、20%作为示例压力情景，它们不是对未来的概率预测。商品当前可盈利，但在预计到货日之前利润可能消失，要同时标注报价时点与可发货日。

### 共用的数据诊断

- 同品匹配：优先 JAN/EAN/UPC、品牌货号和准确规格；标题相似或图片相似只产生候选配对。
- 单包与整盒、全套与散件、新旧与缺附件、税前与含税、币种和优惠资格必须分清。
- 保存原值、币种、汇率快照、价格类型、来源链接、采集时间、规格及采集状态。
- 判断同款与费用完整性先于利润排序。少一项必要费用就显示“暂不能确认净利”，不能按零算。
- 把历史成交、当前询价、当前可执行买价、本人已成交订单分开；历史卖出不能升级为已有买家。
- 报告样本量、覆盖时间和缺失字段。自己从现在开始采集到出发只有约 21 天，拿不到历史接口时不能凭新爬虫补出 90 天历史。
- 已售数/在售数可作特定样本的供需比，不能直接称为你的售出概率，也不能混用不同平台的 sell-through 定义。

## 4. AI 与计算规则的分工（建议）

AI 适合提取日文规格、归纳品相/缺件、发现疑似同款、总结发售或再版消息、解释推荐和拒绝理由。金额计算、费用是否齐全、库存数量、日期、预算约束由明确规则处理。

先用可解释的判断，不在没有真实交易数据时训练“卖出概率模型”。例如：

1. 同品/可售/可携带和交付条件有任一不成立 → 暂缓。
2. 必要成本或需求证据缺失 → 待核验。
3. 成本完整后计算采购上限与压力情景。
4. 根据持有型/周转型排序，并解释占资金、占行李和利润的取舍。
5. 每次成交记录预计利润与实际利润之差，找出错在售价、运费、税费、品相还是周转时间。

示例，仅演示算法：预计售价 800 元，平台和履约等其余成本 120 元，目标利润 100 元，则采购上限为 580 元。若采购 580 元后售价降为 720 元且其余成本仍为 120 元，利润仅 20 元。实际平台费若随售价变化，应重新计算；不能用此示例当作某商品报价。

## 5. 现有项目和市场做法的差距

本轮只读检查，未执行真实抓取测试，未修改业务代码。

| 现有文件/数据 | 观察 | 含义 |
|---|---|---|
| arb/live_search.py | 有 Buyee/eBay/日亚页面读取、解析和粘贴 HTML 回退；eBay 搜索解析重点为标题/价格/链接 | 已有起点，但这些字段不足以验证完整的同款历史成交与销售速度；网络可用性需实测 |
| arb/scoring/score_sku.py 与 recommend.py | 保留静态 SCORE_TABLE、按路线固定分数和默认推荐入口 | 这些分数不是市场预测；未追踪当前首页每个调用路径，因此不声称整个页面都用静态分数 |
| arb/opp/evidence.py | 已区分 retail/bid/buyback/sold/ask/heat 等证据 | 应复用；注意历史 sold 只是预计卖价依据，不是当前保证成交 |
| arb/opp/finance.py | 有净利、资金天数、预测误差等函数；费用缺值在函数内有转零逻辑 | 接入真实采集前需确认调用方对未知费用的拦截，避免得到虚高净利；本轮未做完整调用审计 |
| 旧 14 条候选 | 多数目标为闲鱼但备注卖价使用 eBay 参考 | 国内售价需要独立验证，不能继续直接使用旧收益排序 |

## 6. 适合十一的最小实践

建议自己保留“跨平台商品身份、两种持有策略、成本、证据与行程”这层；有可靠数据服务时复用数据，避免先自建全市场扫描。

### 第一关：先证明能拿到有用的数据

- [ ] 选 5 个准确 SKU 做样本，覆盖用户会卖的两种策略；数量是试验建议，不是采购数量。
- [ ] 核验闲鱼/得物账号各能读到哪些字段、导出是否可用、价格究竟是什么口径。
- [ ] 对少数对应日本货源验证采集，逐条人工核对规格、价格、库存和到货约束。
- [ ] 每个来源给出成功率、漏项、更新时效和预计维护成本；没有实测不能标“已接通”。

### 第二关：输出真正影响采购的诊断卡

- [ ] 每件给出采购上限、售价依据、完整费用、报价时点、到货/发货期限、资金占用。
- [ ] 闲鱼增加持有与退出方案；得物增加价格变化和发货压力情景。
- [ ] 无证据时输出“待核验及具体缺项”，不能用 AI 填补行情、销量或买家。
- [ ] 人工核对发现错品、过期或缺费用的案例也保留，检查系统能否拒绝这些假机会。

### 第三关：连续观察后才扩大

- [ ] 通过样本后扩至约 20 个观察 SKU，先每天一次快照；这是监测建议，频率仍受来源许可与实际需要限制。
- [ ] 采购前、出发前和发货前重新检查关键价格、库存及订单，不依赖隔夜旧价。
- [ ] 只有利润、可买数量或交期发生影响决策的变化才提醒。
- [ ] 通过诊断且经用户采购决策的货关联本次行程；试买额度仍需用户确认。

本轮完成的是市场调研与差距判断。未订阅收费工具、注册平台、启动持续爬虫、发送买家消息或采购。

## 7. 资料采用与排除

采用的核心资料都在上文就近链接。平台文档用于确认具体平台能力；工具商文档用于确认工具声称提供的功能；Emily 案例仅作为具名卖家工作流示例。Amazon 的销售预测能力不能直接迁移成中国平台的数据可得性。

另看到第三方关于得物商机榜、商品分析和托管出价的报道，但尚未用官方当前说明或用户后台交叉核实，未把这些功能列为个人账号已可用。各种“全量得物/闲鱼 API”广告也没有作为接入依据。

已有业务待办见 [十一东京行动清单](../2026-09-11-golden-week-action-list.md)。本报告补充数据与诊断的研究结论，不将旧任务中尚未执行的核验标为完成。
