主代理负责范围、实际工具、验收和集成；下游先交测试/补丁草稿，合格部分直接采用。未知执行先查原 attempt，不重发。所有请求仅公开源文件和合成数据，不发送记忆、凭据、个人记录或生产库。

## 可持续执行的有界队列

每路按依赖顺序领取下列包，已有结果先复用，下一包必须有独立验收价值：

1. 读取现有实现/测试，Coding Plan 产出明确的失败用例；运行基线与新测试，记录真实 red 及最小反例。
2. 对确认缺陷委派最小修复补丁；逐段审查后应用，跑 targeted tests 与原相关回归。
3. Coding Plan 起草独立参考算法/合成数据生成器；固定种子对照小规模穷举，不照抄待测实现。
4. 扩展有效的变形性质：费用增加不得增加净利、预算不超支、到店/返程不能越界；发现新反例才追加修复。
5. 在相同机器、输入、解释器上记录修改前后基准，中位数及样本范围；结果未显著改善就如实写，禁止推断商业ROI或节省比例。
6. 交叉复核接口/真实调用路径、回归和未解决项，交付可复算样例与算法变更说明；不把缺真实报价归为算法已经解决。

父任务每轮先读 manifest、各路 status/review、Git diff 与最近结果。一次最多三路，已在运行的包不再派发。每轮最多十五分钟；每次提交新下游调用前核截止。三轮无实质增量停止该路径并记录一个原因，不循环重试。

同线程只能绑定一个 heartbeat，因此原 `automation-2` 临时用于本轮每十五分钟续接。原完整配置已在私有运行目录保存为 `original-heartbeat.json`；终止时用原字段恢复每天 01:00 夜班并读回确认。不得删除原夜班，也不得在到期后继续算法任务；首次到期后的唤醒只处理交接和恢复。
