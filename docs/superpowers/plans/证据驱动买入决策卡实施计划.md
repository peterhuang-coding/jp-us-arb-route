# 证据驱动买入决策卡实施计划

## 当前迭代目标

把观察池从“手填一个卖出价”改造成“保存结构化销售依据，并由系统派生保守净收入”的买入决策卡。所有今晚形成的产品结论、边界和后续待办都进入仓库，作为下一轮实现基线。

## 已完成

- [x] 新增结构化销售依据：类型、渠道、金额、净额/毛额口径、销售费用、带时区观察时刻、来源说明、来源链接、备注和准确规格快照。
- [x] 销售毛额扣除费用后才成为净收入；非法费用拒绝保存。
- [x] 只有同渠道、同货号、同配色、同规格、近 72 小时的成交、有效报价或自己的订单可参与买入判断。
- [x] 多条有效依据取最低净收入，作为当前保守退出价。
- [x] 挂牌价仅展示，不参与采购和卖出建议。
- [x] 旧 `net_cny`、`evidence_kind`、`evidence_at`、`evidence` 字段保留兼容，但旧手填值不能直接放行。
- [x] 核价弹窗可追加证据并保留历史，填写不完整时明确阻止保存。
- [x] 商品卡、今日买卖、日计划、工作流和 CSV 使用同一条有效销售依据。
- [x] 规格或渠道改变后旧证据仍保留，但因不匹配自动失效。
- [x] 新增后端校验和前端决策测试，覆盖保守价格、费用、时效、规格、渠道、挂牌与旧字段失效。
- [x] 把 MVP、竞品、数据源、市场漏斗和双机分工写入仓库研究文档。

## P0：真实经营验证

- [ ] 选定一个熟悉品类、一个主要销售渠道和约 10 个准确 SKU。
- [ ] 为每个 SKU 人工录入至少一条可复核销售依据，并记录取数耗时和缺失原因。
- [ ] 选择 1—3 个满足条件的真实批次，完成采购、上架、成交、回款和售后记录。
- [ ] 对比预计净利润与实际净利润，拆解身份错配、售价、费用、库存、交期和退款误差。
- [ ] 记录未售库存、持货天数、占用资金和人工总耗时，避免只复盘成功订单。
- [ ] 根据真实波动验证 72 小时窗口是否需要按品类或渠道调整。

## P1：数据质量与自动采集

- [ ] 设计 `source_observation` 原始观察表，保存抓取时间、原始字段、内容哈希、状态和错误，不只覆盖最新值。
- [ ] 为来源增加独立性等级，区分同一页面重复记录、同平台不同记录和跨平台独立证据。
- [ ] 对已形成最高买价的固定 SKU 接入少量采购侧价格、库存、发售和拍卖截止监控。
- [ ] 增加任务队列、频率限制、指数退避、失败重试、最近成功时间和数据延迟监控。
- [ ] 为页面结构变化、登录失效、验证码和权限限制设置人工待核状态，不静默沿用旧数据。
- [ ] 把提醒质量纳入记录：提醒后是否仍可买、是否通过决策卡、是否最终买到。
- [ ] 先验证平台允许的导出、公开页面和官方接口；涉及登录态和自动化访问时核对平台条款。

## P1：销售与回款账本

- [ ] 将当前整批结算扩展为逐笔销售，支持部分售出、部分回款和剩余库存。
- [ ] 分开记录成交毛额、平台费、物流、退款、售后和最终可用回款。
- [ ] 保存上架时间、成交时间、回款时间和持货天数。
- [ ] 允许一个采购批次拆到多个销售渠道，并按数量分摊真实成本。
- [ ] 增加预测版本快照，避免后续更新行情覆盖当时的买入依据。
- [ ] 输出实际利润/人工小时、资金回收时间、未售占资和预测误差。

## P2：MacBook Pro 与 Mac mini 分层

- [ ] Mac mini 部署常驻数据库、API、调度器、异步采集 worker 和备份。
- [ ] MacBook Pro 保留浏览器登录、验证码、人工同款确认、出价/付款和旅行执行。
- [ ] 定义两层同步协议与幂等键，避免断网重试产生重复证据或重复执行记录。
- [ ] 对服务健康、任务积压、抓取失败、数据过期和备份状态建立只读状态页。
- [ ] 凭证只保存在本机安全存储或环境变量中，不进入仓库、日志和证据文本。
- [ ] 第一阶段仅生成提醒和人工待办，不实现无人值守自动付款或绕过平台风控。

## P2：盯潮式机会感知

- [ ] 建立发售日历，记录官方时间、地区、资格、取货窗口和来源。
- [ ] 支持补货、价格变化、拍卖截止与突袭事件的统一事件模型。
- [ ] 事件必须关联准确 SKU 或进入“待匹配”队列，不能凭关键词直接生成买入建议。
- [ ] 仅当事件对应 SKU 已有有效销售证据和最高买价时，生成高优先级执行提醒。
- [ ] 记录提醒发出、人工确认、提交、成功购买和失败原因，形成抢购转化漏斗。
- [ ] 在证明提醒转化价值前，不扩展为泛资讯流或社区产品。

## P3：可选扩展

- [ ] 在国内路径完成闭环后，再评估日本或海外平台转售的账号、收款、税务、鉴定和物流条件。
- [ ] 对重复成交的品类建立补货和库存上限，不用单次高利润外推长期收益。
- [ ] 基于真实交易误差评估 AI 同款识别、异常样本解释和刊登文案辅助。
- [ ] 只有在规则稳定、平台允许、误买风险可控时，讨论更深的自动化执行。

## 验收口径

软件侧：同一输入在观察池、今日买卖、日计划、CSV 和后端 API 中使用同一条保守销售依据；无效依据全部失败关闭，不能退回旧手填卖价。

业务侧：至少完成 1—3 个真实批次并记录到最终回款；在此之前，所有“值得买”“预计利润”都明确为基于已录入证据的判断，不描述为已验证收益。
